# rule-architect

Generate an advanced rule set for a project: one slim `CLAUDE.md` index + on-demand `docs/*.md` rule files.

Core principle: **rules record only what code cannot tell you.** An agent can run `ls` and read `requirements.txt` by itself; it cannot guess that a model must be registered in two places, or that env must load before config import. Always-loaded context (CLAUDE.md) stays minimal; detail lives in `docs/` and loads only when the topic comes up.

## Output Contract

The deliverable is EXACTLY this shape. Not one big file. Not unlinked docs.

### CLAUDE.md (≤60 lines) — always-loaded index

In order:

1. Project one-liner (what it is, 1–2 lines).
2. **Core Rules** — ≤10 bullets. Only top non-derivable constraints (see §Non-Derivable Filter).
3. **Run commands** — entrypoints, test, migration, in one fenced block.
4. **Quick Reference table** — `| Topic | File |` rows linking every generated `docs/*.md`.
5. **File Layout** — where tests/scripts/docs go; `UPPERCASE.md` = AI/team rules, `lowercase.md` = analysis/reference.

### docs/*.md (each ≤150 lines) — on-demand rule docs

Always generate:

| File | Content |
|---|---|
| `ARCHITECTURE.md` | directory map, stack list, data flow, subsystem roles |
| `CODING_RULES.md` | style, naming, comment language, required patterns — each with a real code example |
| `PITFALLS.md` | traps an agent must know before editing: dual naming, ongoing migrations, runtime drift, version-pinning policies |

Conditional — generate only when the scan detects the observable signal:

| Signal detected (observable predicate) | File |
|---|---|
| A dedicated controller/handler layer directory exists | `CONTROLLER_RULES.md` |
| ≥3 enum/status-code value sets scattered across files (aggregation pays off) | `ENUM_CODES.md` |
| An API layer with response-shape conventions (key naming, envelope, pagination) | `RESPONSE_KEYS.md` |
| ORM models or a migrations/ directory | `DB_RULES.md` |
| deploy scripts, systemd units, or Dockerfiles | `DEPLOY.md` |

Conditional file names are defaults — rename to fit the project (e.g. `API_RULES.md` instead of `RESPONSE_KEYS.md`) as long as the name stays UPPERCASE and appears in the Quick Reference table. Borderline signal → skip the doc; a rule can live in `CODING_RULES.md` until it earns its own file.

Cross-link invariant: every file CLAUDE.md links exists, and every generated `docs/UPPERCASE.md` appears in the Quick Reference table.

Generation marker: the last line of a generated CLAUDE.md is `<!-- generated by rule-architect -->`. Its presence is how §Update Mode is detected on a later run.

## Procedure

1. **Scan** — dispatch parallel explore agents:
   - (a) structure + stack, (b) naming/comment/style conventions, (c) infra patterns (config, DB, logging, DI), (d) tests + scripts layout, (e) `git log` for migrations/renames/drift.
   - Check for existing `CLAUDE.md` / `AGENTS.md` / `.cursorrules`. Existing rule set → switch to §Update Mode. Persona/fluff-only files → ignore, note in report.
2. **Select doc set** — apply the conditional matrix to scan results.
3. **Write docs/*.md** — each rule cites real project evidence. Default form: a `file.py:42` reference. Use an inline snippet only when a reference alone cannot show the pattern (ordering, multi-file coupling, before/after). This keeps docs inside the 150-line budget. Apply §Non-Derivable Filter.
4. **Write CLAUDE.md** — last, after docs exist, so every link is real.
5. **Verify** — run the bundled script, then the quiz test (§Verify). Fix and re-run until pass.

## Non-Derivable Filter

Before recording a fact, ask: **"would one `ls`, one file read, or one grep reveal this?"**

- Reveals it → belongs in `docs/ARCHITECTURE.md` at most. NEVER in CLAUDE.md Core Rules.
- Doesn't reveal it → record it. High-value categories:
  - cross-file couplings ("new model must be added to `models/__init__.py` AND `migrations/env.py`")
  - required ordering ("call `load_project_env()` BEFORE importing config")
  - naming prefixes/conventions with the WHY ("tables use `AIT_` prefix")
  - tempting-but-forbidden acts ("never `create_async_engine` directly — reuse `get_engine()`")
  - ongoing migrations / dual naming ("`Game`↔`Project` rename in progress; check which is canonical")
  - external/runtime facts (server drift, API alias policy, ops-only env files)

## Verify

1. **Script** — `python3 scripts/verify_rules.py <project-root>`. Enforces: link integrity both directions, no `TBD`/`TODO`/placeholder, CLAUDE.md ≤60 lines (hard fail >80), docs ≤150 lines (hard fail >190), UPPERCASE naming in docs links. Exit 0 = pass.
2. **Quiz test** — dispatch a fresh subagent given ONLY the generated rule files (no source code access). Ask 5 questions a working agent would need, e.g. "Where must a new DB model be registered?", "How do I run the test suite?", "What must happen before importing config?". ≥4/5 answered correctly from the rules alone → pass. A failed question names a missing rule: add it, re-verify. The script checks form; the quiz is the ONLY content-quality gate — the rule set is not done until both pass.

## Update Mode

When CLAUDE.md carries the `<!-- generated by rule-architect -->` marker, or the user passes `--update`:

- Re-scan, then **diff-edit only changed sections**. NEVER regenerate whole files — that destroys hand-tuned rules added after generation.
- New detected signal → add the conditional doc + its Quick Reference row.
- Report per file: rules added / removed / changed.

## Finishing

If the `md-en-kr` skill is installed (`~/.claude/skills/md-en-kr` or project `.claude/skills/md-en-kr`), offer once: "md-en-kr로 영어 압축 적용할까?" Apply only on explicit yes. Not installed → skip silently, no mention.

## Common Mistakes

| Mistake | Fix |
|---|---|
| Everything in one CLAUDE.md | Split: ≤60-line index + docs/. That IS the deliverable shape |
| Stack list / directory map in CLAUDE.md | Move to `ARCHITECTURE.md`; index keeps rules and links only |
| Rules without code evidence | Every rule cites `file:line` or a real snippet from THIS project |
| Generated doc missing from Quick Reference | Cross-link invariant; the verify script fails it |
| Update regenerates from scratch | Diff-edit only; whole-file rewrite loses manual additions |
| Skipping the quiz test | Quiz is the only check that measures whether rules actually answer agent questions |
| Recording generic best practices ("write tests", "use meaningful names") | Rules must be project-specific; generic advice wastes always-loaded tokens |
